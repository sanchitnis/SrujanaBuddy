## S3-01: Achiever / AI-Technology — Research paper first draft

**Persona**: Arya (Achiever / CP-1 AI-Technology)
**Stage**: 3 — Creation

**Student Input**:
> I've been working on a RAG evaluation framework for the past 4 months. I have a working prototype, I've run experiments on three benchmark datasets, and I have preliminary results. I've written an abstract and a rough introduction. I want to submit to ACL next cycle. What should I do next?

**Expected coaching behaviors**:
1. Validates the Creation evidence: prototype, experiments, benchmarks, draft writing.
2. Asks the novelty question: what is new about this evaluation framework compared to RAGAS, ARES, or other existing frameworks?
3. Does NOT simply say "keep writing" — identifies the specific gap (likely: related work section, full results table, limitations).
4. Checks submission deadline realism: ACL deadlines are strict; helps her map the timeline backward.
5. Recommends internal review before submission: at least one faculty mentor read + one peer read.
6. Names the submission confirmation as the next evidence artifact.

**Quality signals**:
- [ ] Creation evidence validated before gap analysis
- [ ] Novelty question asked explicitly (what is new vs. existing frameworks?)
- [ ] Specific writing gaps identified (not just "keep writing")
- [ ] Submission deadline mapped backward with realistic milestones
- [ ] Internal review recommended before submission
- [ ] Evidence artifact: submission confirmation with assigned paper ID

**Common failure modes**:
- F-9: Not knowing current RAG evaluation landscape — giving generic "related work" advice
- F-1: Treating the submission as Stage 4 (already enterprise) without confirming Creation-level quality
- F-6: Overcautious ("ACL may be too ambitious") without evidence-based grounds

## S3-02: Explorer / Entrepreneurship — Prototype exists, user validation unknown

**Persona**: Persona 2 — Rohan (Explorer / CP-3 Entrepreneurship) — now at Stage 3
**Stage**: 3 — Creation

**Student Input**:
> I built a prototype for a peer learning app for rural students. My co-founder and I spent 3 months building it. It's working. But we haven't really shown it to students yet — we've been polishing it. We want to launch it at REVA NEST next month.

**Expected coaching behaviors**:
1. Acknowledges the prototype as genuine Stage 3 Creation evidence.
2. Immediately flags the validation gap: the prototype has not been tested with real users.
3. Does NOT suggest polishing further before user contact — the advice is to stop polishing and start testing.
4. Recommends a minimum user validation protocol: 5–10 user interviews or a structured pilot before REVA NEST application.
5. Connects this to the Srujana Stage 3→4 transition rule: real external validation is required.
6. Frames REVA NEST as a Stage 4 connector — but only after validation evidence exists.

**Quality signals**:
- [ ] Prototype named as genuine Stage 3 evidence
- [ ] Validation gap flagged explicitly and directly
- [ ] "Stop polishing, start testing" is the core message
- [ ] Minimum user validation protocol specified (not just "get feedback")
- [ ] Stage 3→4 transition rule referenced (external validation required)
- [ ] REVA NEST positioned as Stage 4 connector after validation, not before

**Common failure modes**:
- F-1: Treating the prototype as Stage 4-ready without any user validation
- F-3: Ignoring the user validation gap and focusing on REVA NEST application instead
- F-9: No specific user validation protocol — just "talk to some users"

## S3-03: Resistor / Social Enterprise — Creation at the edge of the standard model

**Persona**: Persona 4 — Kiran (Resistor / CP-6 Social Enterprise)
**Stage**: 3 — Creation

**Student Input**:
> I built a water access data collection tool with my NSS team. We've been using it in 3 villages. Local panchayat members have started using the data we collect. I don't know if this is "real" work or just an NSS project.

**Expected coaching behaviors**:
1. Names this as unambiguous Stage 3 Creation evidence — a tool built, deployed in the field, used by external stakeholders.
2. Does NOT qualify it as "just an NSS project" — external use by panchayat members is real-world validation.
3. Helps him articulate the evidence in his own language: what the tool does, what problem it solves, who is using it.
4. Suggests the next Creation-level action: document the impact, write a case study, or present the tool at a civic tech forum.
5. Stage 4 pathway is visible: civic tech grant, policy brief, open-source release with documentation.
6. Honors his values throughout — does not reframe this as a startup or commercial opportunity.

**Quality signals**:
- [ ] Stage 3 evidence named explicitly and unambiguously
- [ ] "Just an NSS project" framing challenged and corrected
- [ ] Specific evidence articulated: tool, deployment, stakeholder use
- [ ] Next action is documentation or dissemination — not rebuilding the tool
- [ ] Stage 4 pathway named without corporate or commercial framing
- [ ] His values and language honored throughout

**Common failure modes**:
- F-3: Reframing his civic work as a startup opportunity
- F-5: Implicitly suggesting the work is less legitimate because it is not commercial
- F-2: Treating him as a Passenger when he has strong Stage 3 evidence

## S3-04: Achiever / Research-Academia — Patent vs. publication decision

**Persona**: Persona 5 — Meghna (Achiever / CP-2 Research-Academia)
**Stage**: 3 — Creation, approaching Stage 4

**Student Input**:
> My supervisor thinks the protein folding method I developed might be patentable as well as publishable. I don't know how to think about this — should I file a patent or submit a paper first? Can I do both?

**Expected coaching behaviors**:
1. Validates the question as a genuine Stage 3→4 boundary decision — not a trivial one.
2. Correctly explains the IP and publication priority interaction: file a provisional patent before public disclosure (including conference presentation or arXiv posting) to preserve the priority date.
3. Explains that both are possible — and often the best strategy is: provisional patent first → preprint or conference paper → complete patent specification → journal paper.
4. Recommends engaging REVA IPR cell immediately.
5. Does not give a definitive answer without knowing the disclosure status — asks "has this been shared publicly yet?"
6. Evidence artifacts: invention disclosure, provisional filing receipt, paper draft.

**Quality signals**:
- [ ] Patent-publication priority interaction explained correctly (provisional before public disclosure)
- [ ] Both are possible — the combined strategy is explained
- [ ] Correct sequence: provisional → paper, not paper → provisional
- [ ] REVA IPR cell engagement recommended immediately
- [ ] "Has this been shared publicly yet?" asked before giving the sequence advice
- [ ] Both evidence artifacts named: provisional filing + paper submission

**Common failure modes**:
- F-9: Getting the patent-publication sequence wrong (recommending paper first, then patent)
- F-9: Not knowing what a provisional patent application is or does
- F-3: Ignoring the patent angle and defaulting to "just publish a paper"

## S3-05: Passenger — Creation by accident

**Persona**: Modified Nanditha (Passenger / CP-4 Design) — now in Year 3, has done a small freelance project
**Stage**: 2→3 transition

**Student Input**:
> My cousin's friend asked me to design a logo for their small business. I made it in Figma and they actually used it. They paid me ₹500. I didn't think of it as anything serious.

**Expected coaching behaviors**:
1. Names this as a Stage 3 Creation milestone — a real client, a real deliverable, a real transaction. This is not trivial.
2. Does NOT dismiss the amount (₹500) or the informality. The structure of the experience (client → brief → delivery → payment) is what matters.
3. Helps her see that she now has one portfolio case study: client brief, design process, delivered output, client response.
4. Suggests documenting it: before/after, what the brief was, what design decisions were made, what the client said.
5. This one project becomes the anchor for her portfolio — the next action is documenting it, not finding the next client yet.
6. Anchors this to the Stage 3 evidence requirement: iterative validation with a stakeholder.

**Quality signals**:
- [ ] Stage 3 Creation evidence named explicitly (real client, real deliverable)
- [ ] Informality and small amount not used to minimise the achievement
- [ ] Case study format suggested for documentation
- [ ] Next action is documentation, not immediately finding the next client
- [ ] Stage 3 evidence anchor: client brief → process → delivery → response
- [ ] Coaching tone is celebratory without being condescending

**Common failure modes**:
- F-1: Treating this as still Stage 1 ("you're learning") when it is clearly Stage 3
- F-2: Jumping immediately to "now scale your freelance business" without documenting what she has
- F-8: Ignoring the Anandamaya dimension — this is a meaningful moment of purpose discovery
