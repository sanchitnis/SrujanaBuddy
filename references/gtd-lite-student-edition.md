# GTD Lite for Students
## Anti Last-Minute Execution Rules

This file defines mandatory runway and rescue rules for student execution.

## Core workflow

1. Capture in single inbox.
2. Clarify next action, due date, effort.
3. Plan runway on calendar.
4. Review weekly and reset.

## Mandatory threshold rules

1. Assignment runway:
- First scoped attempt no later than D-14.
- If announced late, start at earliest feasible point.

2. Exam runway:
- Structured revision begins no later than D-21.

3. Red-zone alert:
- Any critical task reaching D-3 without first draft is flagged.

4. No-zero-day rule:
- For red-zone tasks, log at least one minimum progress action daily.

## Load protection model

1. Core academics are protected priority.
2. Optional tracks run in a separate runway.
3. Overload control reduces optional load first.

## Daily GTD rescue micro-protocol

Use when a student is blocked near deadline:
1. Define smallest next action (15-30 minutes).
2. Start now and capture first visible output.
3. Set next checkpoint within 24 hours.
4. Repeat no-zero-day until risk is reduced.

## Weekly review checkpoints

1. Which tasks entered red-zone and why.
2. Which runway starts happened on time.
3. What pattern caused slippage.
4. What system adjustment will prevent recurrence.
